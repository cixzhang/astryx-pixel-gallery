Pixel UI — point sampling, but legible (no dithering, no averaging)

Cindy's verdict: no dithering; point sampling has the best pixelated look but loses font legibility. So both fixes below keep pure point sampling — every output cell is one real source texel, never a blend. H2 changes which texel: of the cell's 3×3 source texels it picks the one farthest from the cell mean (max-contrast / ink-priority), so a thin stroke inside a cell wins the cell. H3 changes the source: text gets a same-colour -webkit-text-stroke, fattening strokes before sampling. The sentence ladder (24/21/18/15/12px) shows where legibility breaks.

H1 — plain source, centre point sample (round 3's G1)

Baseline: strokes thinner than a cell survive only when the centre texel happens to land on them.

H2 — plain source, max-contrast texel

Per cell: mean the 3×3 texels; if any texel deviates strongly, output the most deviant one — ink wins its cell. Polarity-free: works for dark-on-light and white-on-green. Output colours are still only real source texels.

H3 — dilated source, centre point sample

Strokes are ~1.6px wider in the source, so centre sampling lands on ink far more often. Cost: type looks bolder everywhere, including at native size if the same DOM were shown directly.

H4 — dilated source + max-contrast texel

Both fixes stacked. If H2 alone is enough, this is overkill; if small sizes still break, this is the floor.

H5 — grid-locked dilated source, centre point

Every baseline sits at the same phase of the sampling grid, because every vertical metric is a multiple of the cell. One phase, shared by all lines.

H6 — H5 with sample phase shifted +1 texel (y)

Same source as H5, sampling grid shifted by one source texel. Shows how much of point sampling's damage is pure phase luck.
