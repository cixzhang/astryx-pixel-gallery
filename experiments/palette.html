Pixel UI — curated palette + ordered dithering

Round 3's G3 failed because uniform per-channel posterise rounds each channel independently and shifts hues. Here every grid cell's averaged colour (the G2 sample) is mapped to the nearest colour in a curated palette — the palette below, which pins the UI's own flat design colours exactly, so flat areas map 1:1 with zero shift. Photos and AA gradients quantise to the palette's tones; Bayer 8×8 ordered dithering hides the banding. The palette is data: one JS array feeds both the shader uniform and the swatch strip.

G2 reference — mip-average, no palette

The best non-palette result from round 3: perfect grid, averaged colours, unlimited palette (AA greys everywhere).

G4 — curated palette, nearest colour, no dither

Flat UI colours should be pixel-exact (they are in the palette). Gradients/photo areas snap to palette tones — watch for banding.

G5 — curated palette + Bayer dither (0.15)

The averaged colour is offset by the Bayer threshold before the nearest-colour lookup, so neighbouring cells pick neighbouring palette entries and gradients dissolve into pattern instead of bands.

G6 — curated palette + Bayer dither (0.30)

Double the dither amplitude: smoother gradients, but flat areas and text edges may start to sparkle. The dose is the question.

G7 — palette + distance-gated dither (0.30, gated)

The fix for G5/G6's speckle: dither amplitude is multiplied by how far the averaged colour sits from the nearest palette entry. Flat UI colours are already in the palette (distance ~0 → no dither, no speckle); only genuine gradient/photo cells — the avatar — get the full dither.
